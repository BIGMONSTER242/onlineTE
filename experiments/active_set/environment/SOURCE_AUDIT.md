## Verified behavior

- Local launch is one coordinator with multiprocessing workers and local gRPC, not a verified complete hierarchical WAN deployment.
- Worker chunks cover consecutive sorted OD commodity IDs. K=N(N-1) must be divisible by the worker count. The adapter chooses the largest divisor no greater than the configured maximum (default 4). Therefore synthetic6 uses 3 workers, not 4 or 6 source workers. C2 source selection is independent of these computational chunks.
- The gRPC coordinator takes a plain mean of per-worker means, appropriate only because the chunks are equal-sized. C3 regrouping is not implemented.
- Worker path-split state is `_dense_solver._Y_tk` (path index first, commodity index second). Raw flow is the split times that worker's actual demand. The adapter exports both directly at `report_chunk`, without recovering flows from aggregate link loads or solving an LP.
- Input path tables are converted into exact `PathProvider` chunks. Edge IDs are mapped to the actual NetworkX directed-edge traversal order. No paths are independently regenerated by the workers.
- Console `Obj. Gap` is `2 * outer_infeasibility / outer_inf_bound`, not relative error against an LP optimum. When `ScaleWithCapacity=False`, `outer_inf_bound` is capacity norm squared divided by square root of edge count; simply changing evaluation optimality tolerance does not tighten this stopping condition.
- Cold-start uses an unbounded spinner rather than `OuterLoopRounds`. The adapter's coordinator subclass stops after the explicit 1000-iteration safety cap. It retains the exact original update implementation and can export the final state at that cap.
- Regression mode retains the original 0.05 residual stopping threshold. Initialization multiplies the denominator by 0.001, equivalent to a 0.00005 threshold in the original scale. QP parameters, precision, PGD, ADMM steps, inner iterations and momentum are unchanged. Reaching the cap is recorded as `iteration_limit`, never as residual convergence. This candidate can satisfy the separate D0 quality requirement only after independent validation.
- The original worker reports `(perf_counter_ns()-start)//1000`, i.e. microseconds despite the protocol's runtime naming; coordinator multiplies by 1000. Adapter timers are separate nanosecond wall/CPU measurements and do not reinterpret that field. Summed measured CPU scope is explicitly recorded; no WAN or speedup claim is supported.
